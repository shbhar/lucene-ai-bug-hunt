Scalar quantization's dynamic confidence interval stops comparing quantile pairs once identical vectors fill one vector's neighbour list

ScalarQuantizer.fromVectorsAutoInterval (the dynamic confidence interval) should keep the quantile pair that best preserves nearest-neighbour scores, but one sampled vector whose ten nearest neighbours are identical vectors, as with 11 identical vectors, makes every pair score 0.0, so it returns its grid's first pair whatever the neighbour scores say. Nothing fails; recall effect unmeasured.

The finding in 30 seconds

#

One neighbour list with no score spread switches the whole quantile search off.

Background: the dynamic confidence interval

#
  1. Scalar quantization stores each float component as a small integer (4 or 7 bits) by scaling it between a lower and an upper quantile.
  2. With the dynamic confidence interval, fromVectorsAutoInterval samples up to 1,000 vectors, finds each one's ten nearest neighbours among them, and tries candidate (lower, upper) pairs from a 16 x 16 grid.
  3. For each pair it scores how well quantized neighbour scores track the float scores, one term per sampled vector, averaged. The pair with the highest average wins.

The finding, step by step

#
  1. You quantize vectors with the dynamic confidence interval (confidenceInterval = 0 on the Lucene99 scalar-quantized format in 9.11.0 to 10.3.2, or ScalarQuantizer.fromVectorsAutoInterval directly). For 20 random 8-dim vectors at 4 bits it picks the pair (-0.96047044, 0.957112).
  2. You add 11 identical vectors far from the rest (every component 10). They change neither the candidate grid nor any original vector's ten nearest neighbours, so you expect the same pair.
  3. Instead you get (-0.9538363, 0.9618902), the grid's first pair. Each copy's ten neighbours are the other copies, all with score 1.0, so its term 1 - errors.var() / scoreVariance is 0/0 = NaN.
  4. That one NaN makes the average NaN for every candidate pair; a fallback maps NaN to 0.0, every pair ties at 0.0, and the first pair tried wins. No error is raised: the quantizer is valid, but it was chosen without looking at the neighbour scores.

Who is affected

#

Only the dynamic confidence interval: in 9.11.0 to 10.3.2, Lucene99 scalar-quantized fields with confidenceInterval = 0 (not the default) at every flush and at merges that recompute the quantiles; since 10.4.0, only direct callers of the public method, such as downstream copies of that writer. It takes identical vectors filling a sampled vector's ten nearest neighbours, e.g. 11 duplicate embeddings.

Mechanism, terms and numbers652 words

With the dynamic confidence interval, ScalarQuantizer.fromVectorsAutoInterval tries a grid of candidate (lower, upper) quantile pairs and keeps the pair whose quantized nearest-neighbour scores track the float scores best: one term 1 - errors.var() / scoreVariance per sampled vector, averaged. If one sampled vector's ten nearest neighbours are identical vectors, as with 11 identical vectors, their float scores tie and they quantize alike, so that term is 0/0 = NaN for every candidate pair. The NaN makes every average NaN, the fallback Double.isNaN(corr.mean) ? 0.0 : corr.mean (added in #13374 for a segment with a single vector) scores every pair 0.0, and the search keeps the first pair it tried. One uninformative neighbour list thus erases all the informative ones, and which pair wins is set by the grid's loop order, not by the correlation (the pair's values still come from the data's quantiles). In this form the quantizer is still finite and valid, nothing fails, and no recall loss has been measured. It is in every release from 9.11.0 to 10.6.0 and on main; Lucene's own writer reached it in 9.11.0 to 10.3.2 with the non-default confidenceInterval = 0 (at every flush and at merges that recompute the quantiles), and since 10.4.0 only direct callers of the public method do.

The mechanism (main 5adff78bb168, ScalarQuantizer.java)

#
  1. Sample and grid. fromVectorsAutoInterval (:315-415) samples at most 1,000 vectors (:326). With at most 1,000 vectors, quantiles are estimated per full batch of min(SCRATCH_SIZE, vector count) vectors (SCRATCH_SIZE = 20; :79, :341-356); with 20 or more vectors a trailing partial batch is not used for the quantiles, but every vector is sampled. The estimates give 16 lower and 16 upper candidates (:399-406). The comment at :407-409 states the goal: "find the best candidate pair by correlating the true quantized nearest neighbor scores with the float vector scores".
  2. Neighbour lists. findNearestNeighbors (:512-544) keeps each sampled vector's top 10 neighbours and the variance of their float scores (:540); OnlineMeanAndVar.var() (:625-627) is 0 when the ten scores are equal. For a copy among 11 identical vectors, the ten neighbours are the other copies, each with EUCLIDEAN score 1 / (1 + 0) = 1.0, so scoreVariance = 0. With 10 far-away copies, each copy's list also holds one original vector, and nothing breaks; but 10 copies that are another sampled vector's ten nearest neighbours trigger it too (the 20 vectors, 10 copies of (10, ..., 10) and one (10.5, ..., 10.5) give the grid's first pair).
  3. The NaN term. For each candidate pair, scoreErrorCorrelation (:657-681) quantizes every sampled vector and its neighbours and collects the score errors (:670-677). The copies quantize to identical bytes, so their errors are equal and errors.var() is 0. corr.add(1 - errors.var() / scoreVariance) (:678) adds 1 - 0f/0f = NaN, and OnlineMeanAndVar.add (:618-623) makes the mean NaN, whatever the other terms are.
  4. The fallback. return Double.isNaN(corr.mean) ? 0.0 : corr.mean; (:680) gives every pair 0.0.
  5. Selection. candidateGridSearch (:441-505) starts at maxCorr = Double.NEGATIVE_INFINITY (:448) and keeps a pair only if mean > maxCorr (:472 coarse pass over every fourth candidate, :497 fine pass in the best quadrant). The first valid pair scores 0.0 > -Infinity and is kept; no later 0.0 is greater. The result is (lowerCandidates[0], upperCandidates[0]), which the constructor accepts (:414).

The numbers

#

20 seeded random 8-dim vectors with components in [-1, 1), EUCLIDEAN, 4 bits: ScalarQuantizer{minQuantile=-0.96047044, maxQuantile=0.957112, bits=4}. The same 20 plus 11 copies of (10, ..., 10): ScalarQuantizer{minQuantile=-0.9538363, maxQuantile=0.9618902, bits=4}, exactly the grid's first coarse pair computed from the 20 vectors. The copies are the trailing partial batch, so the grid is unchanged, and every original is closer to the 19 other originals than to any copy, so every original's neighbour list is unchanged.

Exposure and likelihood359 words
  • Who is hit. In 9.11.0 to 10.3.2, Lucene's Lucene99ScalarQuantizedVectorsWriter calls the method at every flush, and at merges that recompute the quantiles (every 4-bit merge; a 7-bit merge only when the segments' stored quantiles differ too much or one has none, otherwise the merge keeps their size-weighted average), when Lucene99ScalarQuantizedVectorsFormat or Lucene99HnswScalarQuantizedVectorsFormat is built with confidenceInterval = 0; the default is null. Since 10.4.0 (#15223) that writer lives in backward-codecs test sources, so Lucene has no in-tree production caller, but the method stays public, static and not deprecated, and downstream copies of the writer (Elasticsearch, the OpenSearch k-NN plugin) still call it for a confidence interval of 0.
  • What it takes. One sampled vector whose ten nearest neighbours are bit-identical vectors, such as duplicated or placeholder embeddings: 11 or more identical sampled vectors do it under EUCLIDEAN, and 10 do when they are another sampled vector's ten nearest neighbours. In a segment of more than 1,000 vectors such a group must land in the 1,000-vector reservoir sample (:359); for 11 copies, a copy rate of about 1.1% of the segment gives an expected 11 in the sample, not a guaranteed 11 (derived from :326, :359 and :410). Ten tied but distinct neighbours give a related -Infinity form instead (see Suggested fix).
  • What they get. In the identical-vector form, the grid's first pair instead of the best-correlated one, silently. It lies inside the searched range, so the quantizer is valid. With the copies inside the data (200 random 8-dim vectors plus 11 copies of one of them, 5 seeds), stock main returned the same pair for 4 and 7 bits every time, since the grid corner does not depend on bits, while the fix picked a different, data-driven pair in 9 of 10 cases.
  • Not claimed. Any recall or score-accuracy loss (not measured), any exception, any index corruption. The repro calls the public method directly; it is not an end-to-end run of the 9.11.0 to 10.3.2 writer's flush or merge (an independent review also reproduced the collapse on vectors written with IndexWriter and read back).
  • Priority Low. Opt-in, rare input, and a valid result.

Why it looks unintended

#
  • The format promises "determining the most accurate pair"; the code says it picks "the best candidate pair by correlating" scores. With every pair at 0.0, no correlation is used.
  • The NaN-to-0.0 fallback (#13374) was written for a single-vector segment with no neighbour lists, not for one tied list among informative ones.
  • Duplicate vectors are legal input.
The full argument210 words
  • Contract. Lucene99ScalarQuantizedVectorsFormat (:86-88, backward-codecs; the core format in 9.11.0 to 10.3.2): "When 0, the quantiles are dynamically determined by sampling many confidence intervals and determining the most accurate pair." ScalarQuantizer.java:407-409: "find the best candidate pair by correlating the true quantized nearest neighbor scores with the float vector scores". ScoreErrorCorrelator javadoc (:630-633): "This is used to find the best quantile pair for the scalar quantizer."
  • History. The unguarded term came with #13197 (07d3be59af8, benwtrent, 2024). The fallback came with #13374 (3d671a0fbef, ChrisHegarty, 2024), "Fix bug in SQ when just a single vector present in a segment", whose message says "The score error correction is calculated to be NaN, as there are no score docs or variance." Here 20 of 31 lists are informative and the fallback still erases them; the PR does not discuss that case.
  • Tests. No upstream test uses duplicate vectors with the auto interval. TestScalarQuantizer.testTinyVectors only asserts non-null, noting "the quality of the quantization might be poor, but this is expected as sampling size is tiny" (TestScalarQuantizer.java:52-54); this collapse does not depend on sample size.
  • Legal input. The only precondition is function != COSINE (ScalarQuantizer.java:321); the repro uses EUCLIDEAN, finite vectors and FloatVectorValues.fromFloats.
The devil's-advocate check160 words

The case for intended: the method has no javadoc of its own; scalar quantization is "a lossy transformation" (ScalarQuantizer.java:37) and the grid search is a heuristic; in the identical-vector form the result is still a valid quantizer, and since the grid spans only the range between two quantile estimates, the corner pair is close to the best one (0.007 and 0.005 apart in the repro); and on main Lucene no longer calls the method in production.

Why it still holds: the objective is not degraded but switched off: the answer is the grid's loop-order corner, the same for every bit width, and one tied list among up to 1,000 overrides all the others. The expectation does not depend on a particular fix: the tied list's term is the same undefined 0/0 for every pair, so any pair-independent value for it (skip it, 0 or 1) keeps the 20-vector choice. The counter-case sets the impact (Low), not the intent.

Suggested fix

#

Recommended Skip neighbour lists with no float-score spread (validated)

In ScoreErrorCorrelator.scoreErrorCorrelation, add a vector's term only when its neighbours' float-score variance is above 0, and return 0.0 only when no vector contributed (+5/-2 lines). A tied list carries no signal, so skipping it restores the data-driven choice. With it the repro and the other 20 quantization tests pass, and so do 65 Lucene99 scalar-quantized format tests.

Trade-offs

  • Results change only for inputs with a list that has no float-score spread; every list with positive variance contributes as before.
  • It also removes a related form at the same line: ten tied but distinct neighbours (for example the ten points ±0.1·e_i, i < 5, as the origin's neighbours) quantize to unequal errors, so the term is 1 - x/0 = -Infinity. Any later finite term turns the mean into NaN, which again gives the grid's first pair; but if the tied vector is the last one sampled, every pair's mean is -Infinity, no pair beats maxCorr = -Infinity (:448, :472, :497), and the method returns its initial (0, 0) (:449-450), which the constructor widens to (-15, 15) at 4 bits and (-127, 127) at 7 bits (:102-105). With the fix the result is the same in both orders. Noted, not a separate claim.
  • scoreVariance > 0 also skips a NaN variance (a list with a single neighbour, where var() is 0/0), which carries no spread either; that is slightly broader than skipping only zero.
  • No format change: existing segments keep their stored quantiles; new flushes, and merges that recompute the quantiles, pick a data-driven pair (a 7-bit merge that reuses stored quantiles keeps their average). Cost: one comparison per sampled vector and candidate pair.
  • Open PR #16847 casts scoreDoc.doc in the same loop; at most a trivial textual conflict.

#
