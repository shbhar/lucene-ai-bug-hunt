new CharArraySet(858_993_460, false) never returns: the int table-size doubling overflows to 0

Ask a CharArraySet or CharArrayMap for a capacity of 858,993,460 and the constructor never returns: its table size doubles in an int past 2^30 to 0 and stays there, while one less fails at once with OutOfMemoryError on a 1 GB heap. Every release since 2.3.0 is affected; no Lucene call site picks such a size itself.

The finding in 30 seconds

#

A CharArraySet or CharArrayMap (the sets behind stop words, keywords and stem overrides) picks its starting hash-table size in the constructor, from the capacity you pass.

  1. Create a set with a size hint: new CharArraySet(858_993_460, false) (or pass a collection, map or stop-word list of that size). The constructor doubles a table size from 8 until it reaches startSize + startSize/4 = 1,073,741,825.
  2. You expect it to return or throw, as one value lower does: new CharArraySet(858_993_459, false) fails at once (23-27 ms) with OutOfMemoryError on a 1 GB heap.
  3. Doubling reaches 1,073,741,824 (2^30) after 27 steps, one short of the target. The next doubling overflows the int to -2,147,483,648, the next gives 0, and 0 doubled stays 0, so 0 < 1,073,741,825 is true forever.
  4. The constructor spins on one CPU before allocating its table, ignores Thread.interrupt() and never returns or throws, with assertions on or off. Every capacity up to 1,717,986,918, and every one at or below -1,717,986,919, hangs the same way.

Who is affected

#

Only code that asks for a capacity from 858,993,460 to 1,717,986,918, or at or below -1,717,986,919 (say, from an overflowing int product), or passes a collection of that size. No default setup does, and no Lucene call site picks such a size itself. The effect is a silent, uninterruptible CPU spin instead of an error.

Mechanism, terms and numbers404 words

CharArrayMap(int startSize, boolean ignoreCase), and CharArraySet(int, boolean) which delegates to it, pick a hash-table size by doubling an int from 8 until it is at least startSize + (startSize >> 2). When that target is above 2^30, the largest power of two an int holds, the size goes 2^30, Integer.MIN_VALUE, 0, and stays 0, so the constructor spins forever before allocating its table. That happens for startSize from 858,993,460 to 1,717,986,918 and at or below -1,717,986,919, also through CharArraySet(Collection, boolean), CharArrayMap(Map, boolean) and StopFilter.makeStopSet(List, boolean), in every release since 2.3.0. One value lower fails at once with OutOfMemoryError on a 1 GB heap. The trigger is contrived: no Lucene call site picks such a size itself, and, by reading, the map cannot add that many keys without an error anyway.

The loop

#
// CharArrayMap.java:54-62 at 5adff78bb168
public CharArrayMap(int startSize, boolean ignoreCase) {
  this.ignoreCase = ignoreCase;
  int size = INIT_SIZE;                          // 8
  while (startSize + (startSize >> 2) > size) {  // line 57
    size <<= 1;                                  // line 58
  }
  keys = new char[size][];                       // never reached
  values = (V[]) new Object[size];
}

For startSize = 858,993,460 the target is 858,993,460 + 214,748,365 = 1,073,741,825 = 2^30 + 1. Doubling from 8 reaches 2^30 after 27 steps, still one short; 2^31 does not fit in an int, so the next step gives -2,147,483,648 and the one after gives 0, which never grows again.

Entry points

#

CharArraySet(int, boolean), CharArraySet(Collection, boolean) and CharArrayMap(Map, boolean) (both this(c.size(), ...)), and StopFilter.makeStopSet(List, boolean) (new CharArraySet(stopWords.size(), ...)). A set or a stop set built from Collections.nCopies(900_000_000, "x") spins at line 58 too. The spinning thread is still alive 1 s after Thread.interrupt() (for 858,993,460 and Integer.MIN_VALUE).

Exposure and likelihood272 words
  • Who is hit. Callers of CharArraySet(int, boolean) or CharArrayMap(int, boolean) with such a capacity, or of CharArraySet(Collection, boolean), CharArrayMap(Map, boolean) or StopFilter.makeStopSet(List, boolean) with a collection whose size() is in the positive range.
  • What happens. The calling thread spins on one CPU forever. The table arrays are allocated only after the loop, so no heap limit ends it, nothing is logged, and Thread.interrupt() has no effect. Assertions on or off make no difference.
  • Scale. Stop, keyword and stem-override sets come from word lists far smaller than this. AbstractAnalysisFactory's new CharArraySet(files.size() * 10, ignoreCase) reaches the hanging range only with 85,899,346 or more word files in one comma-separated list. One public route forwards a caller's number: SuggestIndexSearcher.suggest(query, n, true) builds TopSuggestDocsCollector(n, true), which calls new CharArraySet(num, false), but only after a PriorityQueue of num + 1 slots (about 3.2 GiB of references at 858,993,460, with compressed oops); on a heap too small for that queue it fails with OutOfMemoryError first (read, not run).
  • The positive range could never work. By reading, put stores a new key, increments count and then rehashes when count + (count >> 2) > keys.length; rehash() doubles keys.length, which overflows at 2^30 slots, so the new table allocation throws NegativeArraySizeException. The 858,993,460th new key is stored and counted but its put throws, and so does every later new key: the map cannot add more than 858,993,459 keys without an error (that rehash site was not run and is not claimed). The fair expectation is a loud error, not a bigger map.
  • Age. Unchanged since 2.3.0 (2008); no public report of it was found.

Why it looks unintended

#
  • The javadoc promises "enough capacity to hold startSize terms" and states no range and no @throws; a constructor must return or throw.
  • One value lower fails loudly with OutOfMemoryError; only the overflowing range hangs.
  • PriorityQueue rejects unusable sizes "to prevent confusing OOME", and the internal hppc hash containers reject negative and too-large sizes.
The full argument140 words
  • The contract. "Create map with enough capacity to hold startSize terms", @param startSize the initial capacity (CharArrayMap; the same in CharArraySet). No range, no @throws.
  • Lucene fails loudly elsewhere. PriorityQueue throws IllegalArgumentException for maxSize < 0 || maxSize >= ArrayUtil.MAX_ARRAY_LENGTH ("Throw exception to prevent confusing OOME"); HashContainers.minBufferSize throws for a negative size and BufferAllocationException above its maximum table length.
  • Nothing covers it. TestCharArraySet, TestCharArrayMap and TestRandomChains (random.nextInt(10)) use small capacities only; no CHANGES or MIGRATE entry mentions a limit; LUCENE-1040 (#2116) and LUCENE-2247 (#3323), which introduced and moved the loop, do not discuss large or negative sizes.
  • History. The unreleased package-private class before LUCENE-1040 used a double load-factor loop that ends (for 858,993,460 it threw NegativeArraySizeException, executed on that source); the public class replaced it with the int test that never ends.
The devil's-advocate check102 words

The case: the positive range asks for more keys than the class can ever add, a negative capacity is misuse, and the class javadoc says "Note that this is not a general purpose class".

Why it fails: that argues for a low priority and for an IllegalArgumentException (or the OutOfMemoryError the neighbouring value already gets), not for a silent endless loop. The javadoc sentence lists missing features (no remove, no shrinking), not undefined behaviour for some sizes. The independent reviewers who built this case (an intended-behaviour devil's advocate, and a reviewer from another model family, OpenAI GPT-5.6) both judged the bug real.

Suggested fix

#

Recommended Reject a negative or oversized startSize with IllegalArgumentException (validated)

Reject sizes the table cannot hold, before the loop: throw IllegalArgumentException when startSize < 0 or startSize + startSize/4 (computed as a long) exceeds 2^30. The repro then passes at once, and so do the 169 tests of lucene/core's analysis package and the module's static checks.

  private static final int MAX_SIZE = 1 << 30; // the largest power-of-two int
  ...
  public CharArrayMap(int startSize, boolean ignoreCase) {
    final long minSize = (long) startSize + (startSize >> 2);
    if (startSize < 0 || minSize > MAX_SIZE) {
      // reject before sizing: past 2^30 slots the int doubling below overflows and never ends
      throw new IllegalArgumentException(
          "startSize must be >= 0 and fit in 2^30 slots; got: " + startSize);
    }
    this.ignoreCase = ignoreCase;
    int size = INIT_SIZE;
    while (minSize > size) {
      size <<= 1;
    }
All options and trade-offs2 options · 614 words

One fix site, CharArrayMap(int, boolean); every other entry point reaches it. Both options were run through gradle in a scratch worktree of 5adff78bb168; only the recommended one was run with the module's tests.

Reject a negative or oversized startSize with IllegalArgumentException (validated) (recommended)

#

Compute the target in long, reject it when it needs more than 2^30 slots or startSize is negative, then double as before. It follows PriorityQueue's "prevent confusing OOME" check.

  private static final int MAX_SIZE = 1 << 30; // the largest power-of-two int
  ...
  public CharArrayMap(int startSize, boolean ignoreCase) {
    final long minSize = (long) startSize + (startSize >> 2);
    if (startSize < 0 || minSize > MAX_SIZE) {
      // reject before sizing: past 2^30 slots the int doubling below overflows and never ends
      throw new IllegalArgumentException(
          "startSize must be >= 0 and fit in 2^30 slots; got: " + startSize);
    }
    this.ignoreCase = ignoreCase;
    int size = INIT_SIZE;
    while (minSize > size) {
      size <<= 1;
    }

Trade-offs

  • Fails at once with a clear message, independent of the heap; the regression test needs no large allocation.
  • Behaviour change: startSize in [1,717,986,919, Integer.MAX_VALUE] and in [-1,717,986,918, -1] gets an 8-slot map today, by accident of the overflow, and would now throw. No in-tree call site picks such a value itself; an external caller passing Integer.MAX_VALUE as "unknown size" would now get an exception.
  • No hot-path cost: one check per constructor call.
  • The fix should also state the accepted range in both constructors' javadoc (@throws IllegalArgumentException); the tested diff leaves the javadoc as it is.

What the checks validated

  • Scratch worktree of 5adff78bb168, gradle, OpenJDK 25.0.3, seed DEADBEEF. Stock: the repro fails with assertions on and off.
  • With the fix: checkGoogleJavaFormat passes; the repro passes with assertions off; the repro plus the whole org.apache.lucene.analysis.* package of lucene/core (22 classes, 169 tests, including TestCharArrayMap, TestCharArraySet, TestStopFilter and TestAbstractAnalysisFactory) passes with assertions on, 0 failures.
  • Re-run on 2026-11-04 with the lint-clean test (same setup): stock, the repro fails with assertions on and off and its file passes ecjLintTest, forbiddenApisTest and checkGoogleJavaFormat; with the fix, :lucene:core:check -x test passes, the repro plus the same 22 classes (169 tests) pass with assertions on, and the repro passes with assertions off (0.006 s and 0.012 s).

Reject a negative startSize and cap the table at 2^30 slots, like java.util.HashMap (repro only) (validated by the checks)

#

Compute the target in long and stop doubling at 1 << 30; reject startSize < 0.

    if (startSize < 0) {
      throw new IllegalArgumentException("startSize must be >= 0, got " + startSize);
    }
    long target = (long) startSize + (startSize >> 2);
    int size = INIT_SIZE;
    while (target > size && size < (1 << 30)) {
      size <<= 1;
    }

Trade-offs

  • Smallest change, HashMap-like.
  • The hanging range then tries to allocate two 2^30-slot arrays (about 8 GiB with compressed oops): OutOfMemoryError on smaller heaps, and on a bigger heap a map that cannot add more than 858,993,459 keys without an error (by reading). Integer.MAX_VALUE also moves from an 8-slot map to that allocation.
  • On the 512 MB test heap the regression test then passes only through an OutOfMemoryError; on a heap of about 9 GB or more it would pass after the 8 GiB allocation (by reading).

What the checks validated

  • The repro passes with assertions off through gradle, but only because the 2^30-slot allocation throws OutOfMemoryError: Java heap space on the 512 MB test heap; gradle's -XX:+HeapDumpOnOutOfMemoryError then wrote a 14.9 MB heap dump. It also passed in a standalone JUnit run (1 GB heap). The module's tests were not run with it.

Downstream note

#

Stop-word, keyword and stem-override sets built from word lists stay far below this size; an application that sizes such a set, or a suggester's result count, from untrusted input must bound that number itself.

How it was found

#

A proof-obligation audit of CharArrayMap's contract: the capacity constructor must return or throw for every int it accepts. Checking the doubling loop against int range showed it cannot reach a target above 2^30, and a one-test repro on the stock jars showed the hang.

The method in full109 words

Method: semi-formal (a proof obligation stated from the contract and checked against the code, witnessed by an executable repro).

  • Obligation. For every int startSize, CharArrayMap(int, boolean) terminates: it returns a map or throws.
  • Check. The loop terminates only if size eventually reaches t = startSize + (startSize >> 2). size takes the values 8, 16, ..., 2^30, then Integer.MIN_VALUE, then 0 forever, so the obligation fails exactly when t > 2^30: startSize in [858,993,460, 1,717,986,918] or at or below -1,717,986,919 (where t wraps).
  • Witness. The one-test repro on main 5adff78bb168, with assertions on and off, and boundary probes at each end of both ranges.

History

#

Introduced with the public class by LUCENE-1040 (e395be3fafc, 2007-11-19), first released in 2.3.0, moved unchanged into CharArrayMap in 3.1.0. Every release run, 2.3.0 to 10.6.0, hangs; never fixed.

Versions tested5 rows

Introduced by e395be3fafc2c08e40adca9d29cff73bfbc80b3e (Subversion r596484, Yonik Seeley, 2007-11-19, "LUCENE-1040: new CharArraySet, make StopFilter directly use it"; #2116; no PR). It made CharArraySet public with while (startSize + (startSize>>2) > size) size <<= 1, replacing the double load-factor loop of the unreleased package-private class (which ends: for 858,993,460 it threw NegativeArraySizeException). 924d7faa684 (LUCENE-2247, #3323, 2010-02-03, first in 3.1.0) moved the loop unchanged into CharArrayMap; later commits changed the constructor around the loop (LUCENE-5859 removed its Version parameter, LUCENE-7329 dropped a CharacterUtils field), moved the class and added braces, but left the loop as it was.

The identical loop is in all 142 release tags of the history clone that contain the introducing commit. Releases 2.3.0 to 8.11.4 were run with a main() form of the same call and the same 10 s bound, because the test needs the 9.x test framework.

You call new CharArraySet(858_993_460, false), or new CharArrayMap(858_993_460, false), CharArraySet(Collection, boolean), CharArrayMap(Map, boolean) or StopFilter.makeStopSet(List, boolean) with a collection of that size(). You expect the constructor to return or throw, as it does one value lower, where it fails at once with OutOfMemoryError. Instead it never returns: the loop doubles an int table size while startSize + (startSize >> 2) is larger, so above 2^30 the size goes to Integer.MIN_VALUE, then 0, and stays 0, and the thread spins forever before allocating anything; the same happens for a startSize at or below -1,717,986,919, where the sum wraps to a large positive value.
