PorterStemFilter's and StempelFilter's javadocs recommend LowerCaseTokenizer, removed in 8.0.0, and PorterStemFilter's example does not compile

The PorterStemFilter and StempelFilter javadocs say to lower-case input with LowerCaseFilter or LowerCaseTokenizer, and PorterStemFilter's example builds a LowerCaseTokenizer. That class was removed in 8.0.0, so the example fails to compile; LetterTokenizer + LowerCaseFilter is the documented replacement.

The finding in 30 seconds

#

Two class javadocs name a tokenizer that 8.0.0 removed; one of them builds it in an example.

What you need to know first

#
  1. An analyzer is a chain: one tokenizer splits text into tokens, then token filters change them. PorterStemFilter and StempelFilter are stemming filters, and they expect lower-case tokens.
  2. Up to 7.x there were two ways to lower-case: the LowerCaseFilter filter, or LowerCaseTokenizer, which split on non-letters and lower-cased in one step. 8.0.0 removed LowerCaseTokenizer; its replacement is LetterTokenizer followed by LowerCaseFilter.

The finding, step by step

#
  1. You want Porter stemming in your own analyzer. PorterStemFilter's javadoc says its input must already be lower case, "so you will need to use LowerCaseFilter or LowerCaseTokenizer", and shows a 7-line MyAnalyzer built on new LowerCaseTokenizer(version, reader). StempelFilter's javadoc gives the same advice.
  2. You copy the example into a class with the imports it leaves out, declare the version and reader it leaves undeclared, and compile against 10.6.0 or main. You expect it to compile and to stem "Running Dogs" to [run, dog].
  3. Instead javac stops with one error: cannot find symbol: class LowerCaseTokenizer. Lucene has not shipped org.apache.lucene.analysis.core.LowerCaseTokenizer since 8.0.0, and none of the 38 jars built from main has it; Class.forName("org.apache.lucene.analysis.core.LowerCaseTokenizer") throws ClassNotFoundException.
  4. Why: LUCENE-8498 removed LowerCaseTokenizer in 8.0.0 and told users to "use a LetterTokenizer followed by a LowerCaseFilter", but did not update these two javadocs. The example's (version, reader) constructor was already gone in 5.0.0.
  5. Written with new LetterTokenizer() and new PorterStemFilter(new LowerCaseFilter(source)), the same example compiles and gives [run, dog]. Nothing wrong ever runs: it is a documentation fix.

Who is affected

#

Anyone who builds an analyzer from the PorterStemFilter or StempelFilter javadoc: the advice names a class missing since 8.0.0, and the example fails to compile on every release since 5.0.0. No configuration or input is involved. Nothing wrong ever runs, and the prose also names the valid LowerCaseFilter, so it is a Low documentation fix.

Mechanism, terms and numbers549 words

PorterStemFilter (analysis-common, the classic English stemmer that EnglishAnalyzer uses) and StempelFilter (analysis-stempel, Polish) stem what they are given and do not lower-case it, so both class javadocs tell you to "use LowerCaseFilter or LowerCaseTokenizer farther down the Tokenizer chain". PorterStemFilter's javadoc then shows a 7-line MyAnalyzer whose tokenizer is new LowerCaseTokenizer(version, reader). LUCENE-8498 removed LowerCaseTokenizer in 8.0.0 (MIGRATE: "use a LetterTokenizer followed by a LowerCaseFilter") and missed these two files, so the advice names a class that Lucene has not shipped since, and the example fails with cannot find symbol: class LowerCaseTokenizer on every release from 8.0.0 to 10.6.0 and on main. Its (Version, Reader) constructor call had already stopped compiling in 5.0.0. With LetterTokenizer and LowerCaseFilter the example compiles and stems "Running Dogs" to [run, dog]. Documentation only: no code is wrong and nothing wrong ever runs.

How it went stale

#
  1. 2001 / 2010: the "LowerCaseFilter or LowerCaseTokenizer" sentence enters PorterStemFilter (initial import) and StempelFilter (LUCENE-2298). Valid.
  2. 2012-09-12: 647b5091697 ("code snippet improvements: fix out of date api usage ...") writes the example with new LowerCaseTokenizer(version, reader). Valid; 4.10.4 compiles it.
  3. 2014: LUCENE-5388 (ab0e85fafed; branch_5x backport 55594bad9b0) removes Reader from tokenizer constructors and edits this snippet's createComponents line, but not its tokenizer line. From 5.0.0 the example does not compile; the class the prose names still exists (deprecated from 7.6.0).
  4. 2018: LUCENE-8498 (c0d2975970d) deletes LowerCaseTokenizer and updates SimpleAnalyzer, StopAnalyzer, CharTokenizer, MIGRATE and CHANGES, but neither of these files. From 8.0.0 the advice names a missing class.
  5. 2020-2026: later edits keep the stale text. LUCENE-9570 reformats both javadocs (8ef6a0da568, 7f8b7ffbcad), #15573 changes the example's markup, and #16063 removes a final modifier from incrementToken(), outside the javadoc.

  • What they do not get. Any runtime effect: both filters behave as their lower-case precondition says, and the compile error is loud.
  • Priority. Low; likelihood "plausible" (anyone who copies the example hits it, every time).

Why it looks unintended

#
  • LowerCaseTokenizer is a real class that 8.0.0 removed on purpose, with a documented replacement, yet the two javadocs name it as current advice in four places.
  • The removal commit updated SimpleAnalyzer, StopAnalyzer, CharTokenizer, MIGRATE and CHANGES, but not these two files.
  • Upstream maintains these examples: 647b5091697 (2012) rewrote this snippet and LUCENE-5388 (2014) updated its signature; #12693 fixed Analyzer's.
The full argument126 words
  • Removed on purpose, with a replacement. MIGRATE.md: LowerCaseTokenizer "combined tokenization and filtering in a way that broke token normalization, so they have been removed. Instead, use a LetterTokenizer followed by a LowerCaseFilter." It was deprecated in 7.6.0 (99df2bd2f35) and deleted in 8.0.0 (c0d2975970d).
  • Missed by the removal. c0d2975970d changed 32 files; PorterStemFilter.java and StempelFilter.java are not among them, and the 10 comments of #9544 never mention them. Both files are byte-identical in 7.7.3 and 8.0.0.
  • Meant to track the API. A 2012 commit titled "code snippet improvements: fix out of date api usage" (647b5091697) rewrote this snippet, and LUCENE-5388 (2014) later updated its createComponents signature but left the tokenizer line; #12693 (2023) fixed the Analyzer class example, closing #12666.
The devil's-advocate check184 words

The case for "intended": Lucene javadoc snippets are illustrative. This one is a fragment (no imports, no enclosing class) and never declared version or reader, Analyzer.java's javadoc uses fictional FooTokenizer placeholders, the build does not compile <pre> blocks, MIGRATE and CHANGES already document the replacement, and later commits edited the class without changing the advice: LUCENE-9570 reformatted both javadoc blocks (2020-2021), #15573 changed the example's markup, and #16063 removed a final modifier from incrementToken(), outside the javadoc.

Why it fails: missing imports and an undeclared variable are gaps a reader fills in; a class that was deliberately deleted is not, and nothing a reader adds makes new LowerCaseTokenizer(...) compile. The prose names it as the way to meet the filter's precondition. MIGRATE confirms the text is stale rather than excusing it, and the later edits were mechanical sweeps (LUCENE-9570 "code reformatting", #15573 "Replace prettyprint with code tag for prism", #16063 "Remove redundant final modifiers"). Every verifier, the executing cross-model reviewer and the adjudication rejected the argument; what remains true is that the impact is small, which is why it is Low.

Suggested fix

#

Recommended Name only LowerCaseFilter; build the example from LetterTokenizer + LowerCaseFilter (validated)

Javadoc only: in both files say "use LowerCaseFilter" instead of "LowerCaseFilter or LowerCaseTokenizer", and write the example as new LetterTokenizer() + new PorterStemFilter(new LowerCaseFilter(source)). Validated with gradle: the new example compiles and stems "Running Dogs" to [run, dog], the en tests and the stempel module pass, and both modules' javadoc renders.

How it was found

#

No formal method. A pass compiled the code examples in Lucene's javadocs against the current jars; this one failed with cannot find symbol: class LowerCaseTokenizer, and a grep for the class found the same advice in StempelFilter. Verifiers, reviewers from another model family (OpenAI GPT-5.6) and an adjudication confirmed it.

The method in full87 words
  • Hunt. The finder extracted the class-javadoc example verbatim from the source and compiled it with javax.tools against the stock main jars: errors for LowerCaseTokenizer and the two undeclared names version and reader. Declaring those two leaves the class as the only error. An API-presence scan over release tags dated the removal, and a grep over the non-sandbox sources found the StempelFilter sentence.
  • Minimized to the one-test class check of the repro section.
  • Tier. Non-formal: compiling documentation code and scanning jars, not a check against exact semantics.

PorterStemFilter's and StempelFilter's class javadocs still tell readers to use LowerCaseTokenizer, which was removed in 8.0.0 (LUCENE-8498), and PorterStemFilter's MyAnalyzer example calls new LowerCaseTokenizer(version, reader), a constructor form gone since 5.0.0, so the example does not compile; the documented replacement is LetterTokenizer followed by LowerCaseFilter (documentation defect)
Area
analysis / stemming filters (PorterStemFilter and StempelFilter class javadoc)
Priority
Low, rank 1022: The PorterStemFilter and StempelFilter class javadocs recommend the removed LowerCaseTokenizer in an example that fails to compile with no runtime effect, and PorterStemFilter is widely read.
Impact class
minor
Impact note
Documentation only, with no runtime effect: a developer who follows the class javadoc of PorterStemFilter (the mainstream English stemmer in analysis-common) or of StempelFilter (analysis-stempel) is told to use a class that has not existed since 8.0.0, and copying the MyAnalyzer example gives a compile error on every release from 5.0.0 to 10.6.0 and on main; the other option the prose names, LowerCaseFilter, is valid, and no configuration, scale or special input is involved.
Summary
PorterStemFilter's javadoc says its input must already be lower case, tells you to use LowerCaseFilter or LowerCaseTokenizer, and shows a MyAnalyzer built on new LowerCaseTokenizer(version, reader); StempelFilter's javadoc gives the same advice. LowerCaseTokenizer was removed in Lucene 8.0.0 (the migration notes say to use LetterTokenizer followed by LowerCaseFilter) and its (Version, Reader) constructor was already gone in 5.0.0, so the example does not compile and the advice names a class that no longer exists. Written with LetterTokenizer and LowerCaseFilter, the example compiles and stems 'Running Dogs' to [run, dog], so only the documentation is wrong.
