MemoryIndex's javadoc example calls new SimpleAnalyzer(version) and new QueryParser(version, ...), constructors removed in 5.0.0, so it does not compile

The only usage example in the MemoryIndex javadoc builds its analyzer with new SimpleAnalyzer(version) and its parser with new QueryParser(version, "content", analyzer). Both constructors were removed in 5.0.0, so the example has not compiled on any release since; dropping the two version arguments fixes it.

The finding in 30 seconds

#

One javadoc example names two constructors that no longer exist.

What you need to know first

#
  1. MemoryIndex (lucene-memory) holds exactly one document in memory. You add fields with an Analyzer and call search(query), which returns a score above 0 when the document matches. The highlighter and monitor modules build on it.
  2. Before 5.0, Lucene analyzers and the classic QueryParser took a Version ("matchVersion") argument. LUCENE-5859 removed those constructors: today it is new SimpleAnalyzer() and new QueryParser(field, analyzer).

The finding, step by step

#
  1. You copy the 12-line "Example Usage" program from the MemoryIndex javadoc. It indexes two fields, parses +author:james +salmon~ +fish* manual~ and prints "it's a match".
  2. You add the 5 imports, declare version (the block never does) and compile against 10.6.0 or main. You expect it to compile and print "it's a match".
  3. Instead javac stops with 2 errors: in line 1, SimpleAnalyzer takes no arguments; in line 5, there is no QueryParser(Version, String, Analyzer). Both errors are about the number of arguments, so no type for version helps.
  4. Why: LUCENE-5859 removed both Version constructors in 5.0.0 and updated the module's test, but not this example. 4.10.4 still compiles it; 5.0.0 through 10.6.0 and main do not.
  5. Remove the two version arguments and the same 12 lines compile and print "it's a match" (score 1.3487055). Nothing wrong ever runs: it is a documentation fix.

Who is affected

#

Anyone who learns MemoryIndex from its javadoc and copies its only usage example, on every release since 5.0.0: two compile errors, with no configuration or special input involved. Nothing wrong ever runs, and javac lists the right constructors, so it is a Low documentation fix.

Mechanism, terms and numbers431 words

MemoryIndex is Lucene's one-document, in-memory index, often used to check whether a single text matches a query. Its class javadoc has one end-to-end "Example Usage" program: build a SimpleAnalyzer, add a "content" and an "author" field, parse +author:james +salmon~ +fish* manual~ with the classic QueryParser and print "it's a match". The program's first line is new SimpleAnalyzer(version) and its fifth is new QueryParser(version, "content", analyzer). LUCENE-5859 removed both Version-taking constructors (trunk 2014; released in 5.0.0 through the branch_5x backport) and left this example, so it has not compiled on any release since 5.0.0: with the Lucene imports, both calls pass the wrong number of arguments, whatever version is declared as. With the two version arguments dropped it compiles and prints "it's a match" on main and 10.5.2. Documentation only: no code is wrong and nothing wrong ever runs.

  • QueryParser.java:91 (classic): public QueryParser(String f, Analyzer a); the other two constructors are protected and take one argument (QueryParser(CharStream) :921, QueryParser(QueryParserTokenManager) :943).
  • The two errors are about the number of arguments, so with the Lucene imports no declaration of version makes the calls compile.
  • Nothing in the build checks it: code inside javadoc <pre> blocks is not compiled, and no {@snippet} is used anywhere under lucene/.

How it went stale

#
  1. 2012-09-12: Robert Muir's "code snippet improvements: fix out of date api usage and add syntax highlighting" (647b5091697 trunk, d8d5bf5e07d branch_4x) wrote both calls in their current form. They were valid; first release 4.0.0.
  2. 2014-08-08: LUCENE-5859 (9938a39a872, Ryan Ernst, "Remove Version from Analyzer constructors") removed SimpleAnalyzer(Version) and QueryParser(Version, String, Analyzer). In the memory module it changed only MemoryIndexTest.java (new QueryParser(TEST_VERSION_CURRENT, "foo", analyzer) became new QueryParser("foo", analyzer)), not MemoryIndex.java.
  3. On branch_4x (cb9beac7079, 4.10.0) the two constructors were only deprecated, so 4.10.x still compiles the example. The branch_5x backport 55594bad9b0 (LUCENE-5944, 2014-09-18) carried the removal into 5.0.0.
  4. Later commits (2014-2015 doclint fixes, LUCENE-9570 reformatting in 2021, #15573 in 2026) changed only the markup around the block.
Exposure and likelihood113 words
  • Who. Readers of the MemoryIndex class javadoc, the class's only end-to-end usage example. MemoryIndex is public and not marked @lucene.experimental; the highlighter (WeightedSpanTermExtractor, MemoryIndexOffsetStrategy) and the monitor (DocumentBatch) build on it.   • Priority. Low; likelihood "plausible" (anyone who copies the example hits it, every time).
