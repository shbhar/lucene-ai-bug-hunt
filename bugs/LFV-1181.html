Automata.makeBinaryInterval stores an empty arc [256, 255] for an open-ended range whose lower term starts with 0xFF, so determinizing a union of such automata throws

For an open-ended binary range whose lower term starts with byte 0xFF, Automata.makeBinaryInterval (behind TermRangeQuery.toAutomaton) adds an empty transition, bytes 256 to 255. Determinizing the union of two such automata, or searching it with an AutomatonQuery, then throws ArrayIndexOutOfBoundsException; a single TermRangeQuery still works.

The finding in 30 seconds

#

Background: range transitions and the determinize sweep

#
  1. A Lucene automaton moves between states on transitions (arcs), each covering a label range [min, max], inclusive; for binary terms the labels are the bytes 0 to 255. TermRangeQuery.toAutomaton(lower, null, true, true) builds the automaton of all terms from lower up: a first byte equal to lower's goes on to check the rest, and any greater first byte goes straight to an accept-everything state.
  2. Operations.union puts several automata side by side under one start state; if two arcs there overlap, the result is an NFA. Operations.determinize turns it into a DFA by sweeping each state's arcs by their boundary points: an arc opens at min and closes at max + 1, and at each point the sweep first closes the arcs that end there, then opens the ones that start there.

The finding, step by step

#
  1. Build two open-ended binary ranges with TermRangeQuery.toAutomaton(lower, null, true, true): every term from {0xFF,'a'} up, and every term from {0xFF,'b'} up.
  2. Combine them with Operations.union and call Operations.determinize. You expect a DFA that accepts {0xFF,'c'}; with lower terms that start with 0xFE the same steps work.
  3. Instead determinize throws ArrayIndexOutOfBoundsException: Index -7 out of bounds for length 9 (AssertionError with assertions on). An AutomatonQuery over the union throws the same during IndexSearcher.count.
  4. Why: with no upper term, the method adds an arc for "first byte greater than the lower term's", [minLabel + 1, 255]; for 0xFF that is [256, 255], which matches nothing. The determinize sweep closes it at point 256 before opening it, so it removes a state it never added.
  5. One range alone still works: a plain TermRangeQuery counts 4 of 4 documents. The same method already skips this arc in its other branch with if (minLabel < 255).

Who is affected

#

Only custom code over binary (non-UTF-8) terms: it must build open-ended ranges whose lower term starts with 0xFF (for example a sortable-encoded int of 2,130,706,432 or more) and union or concatenate them before determinizing or searching. A single TermRangeQuery, Intervals.range and text terms are not affected.

Mechanism, terms and numbers625 words

TermRangeQuery.toAutomaton(lower, upper, includeLower, includeUpper) is a public static helper that calls Automata.makeBinaryInterval (search/TermRangeQuery.java:99-112 at 5adff78bb168). When the upper term is null and the lower term's first byte is 0xFF, the method's max == null branch adds the transition [minLabel + 1, 0xff] = [256, 255] (util/automaton/Automata.java:409), a range with no labels; the same loop's already-diverged branch skips exactly this case with if (minLabel < 255) (:435-437). Automaton.addTransition checks the state numbers but never the range, and keeps the arc (Automaton.java:153-183). A single such automaton stays deterministic and works on the paths tested, so a plain TermRangeQuery counts correctly. But Operations.determinize of the union of two of them throws AssertionError (assertions on) or ArrayIndexOutOfBoundsException: Index -7 out of bounds for length 9 (off) in StateSet.decr, and an AutomatonQuery over the union fails the same way at search time. It came with LUCENE-5879 in 5.2.0 (2015); 5.2.0 to 8.9.0 with assertions off returned a wrong automaton without an exception instead. Only custom code that composes binary range automata is hit; an if (minLabel < 255) guard around that one line fixes it. Priority Low.

The mechanism (main 5adff78bb168, lucene/core/src/java/org/apache/lucene/util/automaton/)

#
  1. The producer (the fix site). In Automata.makeBinaryInterval, at the first byte of the lower term and with max == null, :406-410 add addTransition(lastState, sinkState, minLabel + 1, 0xff) (to the accept-everything sink) and addTransition(lastState, nextState, minLabel). For minLabel 255 the first is [256, 255]. The already-diverged branch of the same loop guards the same arc with if (minLabel < 255) (:435-437). One exception: for the one-byte inclusive lower term {0xFF}, nextState is the sink too (:395-396), so both arcs go to state 1 and Automaton.finishCurrentState merges same-destination ranges (Automaton.java:258-262): only [255,255]->1 is kept, and a union of two such automata determinizes fine. {0xFF} exclusive and every 0xFF-led lower term of two or more bytes keep [256, 255].
  2. Nothing rejects it. Automaton.addTransition checks source and dest (Automaton.java:158-159, plus that a state's transitions are added together) but never min and max, which it stores as given (:178-179). For {0xFF,'a'} the start state has [255,255]->2 and [256,255]->1; they do not overlap, so the automaton stays flagged deterministic and a single TermRangeQuery works (tested).
  3. The union. Operations.union of the {0xFF,'a'} and {0xFF,'b'} automata gives a start state with [255,255]->2, [255,255]->4, [256,255]->1, [256,255]->3. The two [255,255] arcs overlap, so it is a legitimate NFA and determinize (Operations.java:653) runs its sweep.
  4. The sweep. Each arc is recorded with its start at t.min and its end at 1 + t.max (Operations.java:618-621): for [256, 255] both are 256. At a point the sweep handles ends first, statesSet.decr(dest) (:772), then starts, statesSet.incr(dest) (:783). So at point 256, after removing 2 and 4, it decrements state 1, which was never added.
  5. The failure. StateSet.decr asserts the state is present (StateSet.java:59): AssertionError with assertions on. With them off it looks the missing state up anyway and reads a negative slot (:60-61): ArrayIndexOutOfBoundsException: Index -7 out of bounds for length 9 from IntIntHashMap.indexGet. NFARunAutomaton$DState.determinize, which AutomatonQuery uses when the binary automaton is not deterministic (CompiledAutomaton.java:253-257), has the same end-before-start sweep (NFARunAutomaton.java:428-444) and fails the same way during a search.

Exposure and likelihood318 words
  • Who. Code that indexes binary terms, builds open-ended range automata with TermRangeQuery.toAutomaton or Automata.makeBinaryInterval whose lower term starts with 0xFF, and combines them into an NFA: Operations.union then Operations.determinize, or new AutomatonQuery(term, union, true). A leading 0xFF is an ordinary binary value: NumericUtils.intToSortableBytes flips the sign bit (util/NumericUtils.java:178-180), so every int from 2,130,706,432 (0x7F000000) up starts with 0xFF (an example of binary keys; numeric ranges normally use point queries, not term automata).
  • Wider than two such ranges. A later re-check on main also hit the exception for the union of a 0xFF-led range with a 0xFE-led one, and for Operations.concatenate of two 0xFF-led ones; the single automaton, its complement, intersection and minus returned and gave the expected answer for the probe term {0xFF,'c'}.
  • Not affected. A single range: TermRangeQuery search counts correctly, and Intervals.range uses one range automaton (lucene/queries/.../intervals/Intervals.java:285-287). Text: valid UTF-8 never contains the byte 0xFF (Lucene's encoder writes lead bytes up to 0xF4, util/UnicodeUtil.java:165). No Lucene code unions range automata.
  • Opt-in. No configuration is involved; composing automata yourself is the opt-in part, on @lucene.experimental APIs (Automaton.java:43, Operations.java:56, search/AutomatonQuery.java:41).
  • Effect. On 8.10.0 and later, an exception on the calling thread; nothing hangs and the index is not modified (the search path only reads it). On 5.2.0 to 8.9.0 with assertions off, determinize returned a wrong DFA without any exception, one that rejects in-range terms such as {0xFF,'a'} and {0xFF,'c'} (run on 5.2.0, 8.8.2 and 8.9.0; SortedIntSet.decr, where the bad decrement lands, has the same body at every tag in between); whether a search on those releases missed hits was not run.
  • Scale and likelihood. No scale needed: two 2-byte lower terms. Rare: binary 0xFF-led bounds, an open upper end and caller-side composition; no public report was found ("Prior reports"), although the code dates from 5.2.0 (2015).

Why it looks unintended

#
  • The javadoc promises "a new deterministic, minimal automaton accepting all binary terms in the specified interval"; a 0xFF-led lower term is legal.
  • The same loop already skips this arc with if (minLabel < 255) in its other branch.
  • Core treats min > max as empty elsewhere: Automata.makeCharRange returns makeEmpty().
The full argument192 words
  • Contract. makeBinaryInterval's javadoc: "Creates a new deterministic, minimal automaton accepting all binary terms in the specified interval" (Automata.java:279-280). Nothing excludes a BytesRef bound that starts with 0xFF.
  • The method's own guards. The commit that wrote the line also wrote if (minLabel < 255) in the already-diverged branch (:435), maxLabel > minLabel + 1 (:417) and maxLabel > 0 (:464) on the other range arcs; only the max == null arc misses its guard.
  • An empty arc is not a valid label set anywhere in the package. Transition documents both bounds as inclusive (Transition.java:41-45), Automaton.toDot asserts t.max >= t.min (Automaton.java:606), and Automata.makeCharRange returns makeEmpty() for min > max (Automata.java:140-143).
  • Tests. The open-upper tests use only "bar", "" and null as the lower term (TestAutomaton.java:1580-1640), and testMakeBinaryIntervalRandom always passes a non-null upper term (:1478-1486); none composes the result, so the case was never exercised.
  • History. Since 2015 only a whitespace reformat (LUCENE-9570) touched the line; LUCENE-9578 (#10618, 2020) fixed a different edge case of the same method and left this branch alone.
The devil's-advocate check128 words

The strongest case for "intended": Automaton, Operations and AutomatonQuery are @lucene.experimental; passing an inverted range to addTransition is caller misuse, and the failure is loud.

Why it fails here: the inverted range is not the caller's. Core's own makeBinaryInterval builds it from a legal bound, and the experimental tag does not let a documented method return an automaton that determinize, also core, cannot process. What the argument does establish: hand-calling addTransition(s, d, 5, 4) yourself fails the same way and is close to misuse, so that route is not the headline; and the trigger is narrow, hence Low. The verifier assigned to argue "intended" rejected the case for this route; the cross-model reviewer rated its own "intended" argument moderate, and only for the hand-built route.

Suggested fix

#

Recommended Guard the open-upper arc with minLabel < 255 (fix A)

Add the missing guard: wrap a.addTransition(lastState, sinkState, minLabel + 1, 0xff) (Automata.java:409) in if (minLabel < 255), as the method's other branch does. The skipped arc matched nothing, so the accepted terms do not change. The repro passes with assertions on and off, and the 299 tests of the closest suites pass.

Downstream note

#

Downstream code that composes binary range automata, for example over sortable-encoded keys, gets an exception instead of a result; Lucene's own query paths use a single range automaton and are not affected.

How it was found

#

A semi-formal proof-obligation audit of Automaton.addTransition's contract: determinize can only process arcs that are real label ranges. A hand-built empty arc crashed it; a supporting probe found that core's own makeBinaryInterval builds one for a 0xFF-led open-ended range, and a one-test JUnit on the stock main jars witnessed it.

The method in full142 words

Method: semi-formal (a proof-obligation audit of a class's contract, witnessed by an executable repro).

  • The obligation: every arc stored by Automaton.addTransition is a label range that the rest of the package, determinize in particular, can process; addTransition itself checks the state numbers but never the range.
  • A test with a hand-built empty arc next to [0,10] made determinize throw in StateSet.decr. A supporting probe showed that TermRangeQuery.toAutomaton stores [256,255] for a 0xFF-led open-ended range and that the union of two such automata fails the same way, while the 0xFE-led control passes. Because the hand-built route alone is close to caller misuse, the claim was anchored on this producer and its one-test repro.
  • An independent reproducer, an executed cross-model review and a devil's-advocate verifier reproduced it with their own tests, and an adjudication confirmed it ("Prior reports, history and checks").

Only applications that build automata for binary (non-UTF-8) term ranges with no upper term and a lower term starting with byte 0xFF, and then combine two or more of them (Operations.union followed by Operations.determinize, or an AutomatonQuery over the union), are hit: the call throws AssertionError with -ea and ArrayIndexOutOfBoundsException with -da on main and 10.6.0 [exec]; a plain TermRangeQuery search with the same bound still counts correctly [exec], text terms are UTF-8 and never start with 0xFF, no in-tree caller unions range automata, no scale is needed, and every release from 5.2.0 on has the unguarded line (with -da, 5.2.0 to 8.9.0 returned a wrong DFA without an exception instead [exec]).
Summary
You build the automata of two open-ended binary term ranges whose lower terms start with byte 0xFF, TermRangeQuery.toAutomaton(new BytesRef(new byte[] {(byte) 0xFF, 'a'}), null, true, true) and the same with {0xFF, 'b'}, union them with Operations.union and determinize the result. You expect a DFA that accepts every term from {0xFF, 'a'} up, such as {0xFF, 'c'}, as you get when the lower terms start with 0xFE. Instead Operations.determinize throws AssertionError (-ea) or ArrayIndexOutOfBoundsException 'Index -7 out of bounds for length 9' (-da) in StateSet.decr, and an AutomatonQuery search over the union fails the same way, because makeBinaryInterval's open-upper branch adds the transition [minLabel + 1, 0xFF], here the empty range [256, 255], without the 'minLabel < 255' guard its sibling branch has.
