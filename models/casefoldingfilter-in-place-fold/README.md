# Formal models and scripts: casefoldingfilter-in-place-fold

Tools: Python.

These are the working models and scripts this part of the hunt used. Some encode the code as it is (a counterexample is the expected result), others a fixed or correct variant; read the header comment of each file. Paths inside them were replaced by placeholders such as `$LUCENE` (a Lucene checkout) and `$WORK`.

## Findings

- CaseFoldingFilter writes a term with an unpaired surrogate for a word that contains U+1DF95: the Unicode 18 fold table maps this supplementary letter to U+00DF (ß), and the filter's in-place fold cannot make the term shorter, so the term keeps the letter's second UTF-16 unit, the index stores U+FFFD in its place, and behind WhitespaceTokenizer the queries Ma?e, /ma.e/ and Mate~1 no longer find the word 'Ma' + U+1DF95 + 'e', which they find on 10.6.0 (main and branch_11x, both unreleased, since the fold table regenerated by #17010) (finding LFV-1520; [repro](../../repro/LFV-1520/), [finding page](../../bugs/LFV-1520.html))
