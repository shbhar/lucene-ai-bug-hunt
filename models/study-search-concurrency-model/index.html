AI-assisted bug hunt in Apache Lucene

Formal models and scripts: study-search-concurrency-model

Tools: TLA+/TLC, Python

These are the working models and scripts this part of the hunt used. Some encode the code as it is (a counterexample is the expected result), others a fixed or correct variant; read the header comment of each file. Paths inside them were replaced by placeholders such as $LUCENE (a Lucene checkout) and $WORK.

Bugs found

  • IndexSearcher#count hangs forever when Weight#count throws, for example on a query timeout, on a segment split into intra-segment partitions (bug LFV-045; repro · bug page)
  • Reusing a TotalHitCountCollectorManager after a failed search silently returns count 0 or hangs (bug LFV-053; repro)
  • LRUQueryCache's 16 hard partitions give a 0% hit rate with the class-javadoc configuration (main only) (bug LFV-054; repro)
  • A timed-out search reports its partial hit count as TotalHits.Relation.EQUAL_TO (bug LFV-077; repro)
  • TaskExecutor#invokeAll returns while a task is still running if the caller is interrupted (bug LFV-056; repro)

How to run

  • TLA+ with TLC: java -cp tla2tools.jar tlc2.TLC -config <Model>.cfg <Model>.tla (a counterexample trace is the bug when the model encodes the current code).
  • Python: python3 <file>.py; scripts that import z3 need the z3-solver package.
