Formal models and scripts: indexingchain-schema

Tools: Alloy, Python

These are the working models and scripts this part of the hunt used. Some encode the code as it is (a counterexample is the expected result), others a fixed or correct variant; read the header comment of each file. Paths inside them were replaced by placeholders such as $LUCENE (a Lucene checkout) and $WORK.

Bugs found

  • The frozen-FieldType validation cache (#15886) keys a field on its first value's type, so for a field built from several field types a later document skips the per-field schema check (or is checked against stale state after a rejected addBatch), depending on value order, flushes and earlier operations (bug LFV-118; repro · bug page)
  • A rejected document leaves its doc-values skip index type in the field's per-document schema state, so later valid documents with that field are rejected until the in-memory segment is flushed (bug LFV-116; repro)
  • IndexWriter#addBatch marks the frozen FieldType of an earlier rejected document as validated, so later documents with that type skip the per-field schema check (a wrong-dimension vector is stored truncated) (bug LFV-127; repro)
  • A failed addIndexes(Directory...) leaves the incoming fields registered in the writer's field schema, so getFieldNames lists them and later valid documents that use those names differently are rejected until the writer is reopened (bug LFV-124; repro)
