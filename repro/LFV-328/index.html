ArrayUtil.hashCode(char, int, int) javadoc says the end index is inclusive, but the code and its only caller treat it as exclusive (documentation defect; the code is correct and must not change)

Bug LFV-328Area: util / ArrayUtil (hashCode(char, int, int) javadoc)Priority: lowImpact: minorNovelty: new

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

What it shows

The javadoc of ArrayUtil.hashCode(char array, int start, int end) says it hashes the chars from start (inclusive) to end (inclusive), so hashCode({'x','y'}, 0, 0) should hash the one char 'x' and hashCode(a, 0, 1) should depend on a[1]. The loop 'for (int i = end - 1; i >= start; i--)' hashes the half-open range [start, end) instead: hashCode({'x','y'}, 0, 0) is 0 (an empty range) and the ranges [0, 1] of "xy" and "xz" both hash to 120. The code is the intended side (its only caller passes an exclusive end, and every other range method in ArrayUtil documents the end as exclusive), so the fix is one word in the javadoc, 'end (exclusive)'.
