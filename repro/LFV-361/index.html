AI-assisted bug hunt in Apache Lucene

XML query parser: a <Clause> without the occurs attribute, which LuceneCoreQuery.dtd and BooleanQueryBuilder's own code default to SHOULD, is rejected with ParserException 'Invalid value for "occurs" attribute of clause:' (regression since 5.1.0, LUCENE-6270)

Bug LFV-361Area: queryparser / xml (BooleanQueryBuilder)Priority: lowImpact: wrong errorNovelty: new

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

What it shows

You give the XML query parser (CoreParser.parse) a <BooleanQuery> whose <Clause> has no occurs attribute and expect an optional (SHOULD) clause, because LuceneCoreQuery.dtd declares occurs with the default "should", BooleanQueryBuilder.getOccursValue has its own 'attribute absent -> SHOULD' branch, and 5.0.0 and earlier parsed it that way. Instead the whole parse fails with ParserException 'Invalid value for "occurs" attribute of clause:' (nothing after the colon): org.w3c.dom.Element.getAttribute returns an empty string, never null, for an absent attribute, so the 'occs == null' default branch never runs; an explicit occurs="" is rejected the same way. Explicit should, must, mustNot and filter values work as before, and writing occurs="should" is a workaround.

The test shows that CoreParser.parse rejects <BooleanQuery fieldName='f'><Clause><TermQuery>a</TermQuery></Clause></BooleanQuery>, a <Clause> without occurs.

Expected vs actual

Expected: one SHOULD clause f:a (the DTD default and the builder's own null branch); actual (-ea and -da): ParserException 'Invalid value for "occurs" attribute of clause:' (BooleanQueryBuilder.java:81), because Element.getAttribute returns "" and the occs == null check (:72) never matches.
