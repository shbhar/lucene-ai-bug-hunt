Classic Highlighter returns no fragment (null) for text that contains the query term when QueryScorer or QueryTermScorer was given an IndexReader without documents: the IDF weight log(maxDoc / (docFreq + 1)) + 1 is -Infinity for maxDoc 0, so every fragment that holds the term scores -Infinity and no fragment is kept; every release from 1.9 to 10.6.0, branch_11x and main

Finding page for LFV-1526

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

What it shows

You create a Highlighter with new QueryScorer(query, reader, field), or new QueryTermScorer(query, reader, field), where the reader is an index that holds no document, and call getBestFragment on the text 'alpha beta' for a TermQuery on alpha. You expect '<B>alpha</B> beta', which the same call returns without the reader argument or with a reader that holds a document: the reader is documented as the source of IDF weights for scoring fragments, and getBestFragment is documented to return null only 'if no terms found'. Instead it returns null, with no exception: for maxDoc() 0 the IDF factor log(maxDoc / (docFreq + 1)) + 1 is -Infinity, so the term's weight and the score of every fragment that holds the term are -Infinity, and Highlighter keeps only fragments with a score above 0. Every release since 1.9 does it, and it shows only while the reader holds no document at all.

Expected vs actual

  • Expected: getBestFragment returns <B>alpha</B> beta, as it does without the reader argument.
  • Actual: It returns null: java.lang.AssertionError: expected:<<B>alpha</B> beta> but was:<null>.

What the test does: it creates an index with the default IndexWriterConfig and closes it without adding a document, opens a reader on it (maxDoc() is 0), builds a Highlighter with new QueryScorer(query, reader, "f") for a TermQuery on alpha, and expects getBestFragment to return the text 'alpha beta' with alpha marked up, as the same call does without the reader argument. It fails with java.lang.AssertionError: expected:<<B>alpha</B> beta> but was:<null>: no fragment comes back. Only a reader that holds no document does this: with one document in the index the same call returns the fragment (the finding page has those runs). The text and the query are fixed; the test framework draws its analyzer's settings, its directory and its environment from the seed, and the test failed the same way with every seed that was run. On a checkout of the 11.0 branch set V=11.0.0-SNAPSHOT; for the release, put the six 10.6.0 jars from Maven Central (org.apache.lucene: lucene-core, lucene-codecs, lucene-test-framework, lucene-highlighter, lucene-memory, lucene-queries) in place of the six $LUCENE jars. For the Gradle alternative at the end of this page the module is lucene/highlighter; without -Ptests.asserts the build of main and of branch_11x draws the assertion setting from its seed (on for the seed DEADBEEF), and the build of the 10.6.0 sources runs with assertions on; the test fails with either setting.
