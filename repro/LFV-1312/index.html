AI-assisted bug hunt in Apache Lucene

DocBaseBitSetIterator over an empty FixedBitSet with a non-zero docBase throws ArrayIndexOutOfBoundsException (AssertionError with -ea) from its first nextDoc() instead of returning NO_MORE_DOCS, because advance() calls nextSetBit(0) on the zero-length set (latent: no Lucene code builds that shape; since 9.1.0)

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

What it shows

You build a DocBaseBitSetIterator over an empty bit set with a non-zero doc base, for example new DocBaseBitSetIterator(new FixedBitSet(0), 0, 64), the shape you get for a 64-aligned window of documents that turned out to have no matches. You expect its first nextDoc() to return NO_MORE_DOCS, as the same class does with docBase 0 and as BitSetIterator, which its javadoc says it is 'like', does for an empty set. Instead nextDoc() throws ArrayIndexOutOfBoundsException 'Index 0 out of bounds for length 0' (AssertionError 'index=0, numBits=0' with -ea), because advance() returns early only when target >= bits.length() + docBase and otherwise calls bits.nextSetBit(0) on the zero-length set.

Expected vs actual

  • Expected: The first nextDoc() returns NO_MORE_DOCS (2147483647) and the test passes.
  • Actual: java.lang.ArrayIndexOutOfBoundsException: Index 0 out of bounds for length 0 from FixedBitSet.nextSetBit (AssertionError: index=0, numBits=0 with assertions on).
