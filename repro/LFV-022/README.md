# RegExp CASE_INSENSITIVE is not applied to an escaped character inside a multi-item character class

Bug LFV-022 · Area: util / automaton · Priority: low · Impact: silent wrong results · Novelty: new

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

## What it shows

You compile a RegExp with the CASE_INSENSITIVE flag whose character class holds an escaped character next to other items. You expect the escaped character to match both cases. Instead only its literal case matches; all 2,881 cased non-ASCII-letter code points are affected.

## Expected vs actual

- Expected: You expect the escaped character to match both cases.
- Actual: Only its literal case matches; all 2,881 cased non-ASCII-letter code points are affected.
