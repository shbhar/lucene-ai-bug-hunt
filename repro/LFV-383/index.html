Sequential DrillSideways never returns on a segment of more than 2^31 - 2048 documents: DrillSidewaysScorer's int chunk start wraps to Integer.MIN_VALUE, so its union and drill-down-advance loops never exit (released since 4.2.0)

Bug LFV-383Area: facet / DrillSideways (sequential DrillSidewaysScorer, union and drill-down-advance strategies)Priority: lowImpact: hangNovelty: new

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

What it shows

You run a faceted DrillSideways search in the default sequential mode on an index whose single segment holds more than 2,147,481,600 documents, which IndexWriter accepts (MAX_DOCS = 2,147,483,519), and expect it to return its hits as it does on a segment 2,048 documents smaller. Instead DrillSidewaysScorer's union and drill-down-advance loops walk the segment in 2048-document chunks with an int nextChunkStart that wraps from 2^31 - 2048 to Integer.MIN_VALUE before the exit test 'nextChunkStart >= maxDoc' can fire, so the search thread spins forever and the hits of the last chunk are never collected. Through the public API on a real segment of MAX_DOCS documents the stock search did not return within 300 s, while the fixed build returned its 3 hits in 0.033 s.

The test shows that DrillSidewaysScorer's union loop on a segment of IndexWriter.MAX_DOCS documents (simulated: a FilterLeafReader reports that maxDoc()) never ends, because the int chunk start wraps from 2^31 - 2048 to Integer.MIN_VALUE; the test's base iterator stops it after twice the 2^20 chunks.

Expected vs actual

Expected score() to return and collect the last 3 docs; actual AssertionError:... still looping after 2097153 docID() calls, collected [], with -ea and -da.
