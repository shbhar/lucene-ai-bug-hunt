AI-assisted bug hunt in Apache Lucene

SegmentInfos.commit checks delCount and softDelCount against maxDoc one at a time but not their sum, so it publishes a segments_N that readCommit, DirectoryReader.open and IndexWriter then reject with CorruptIndexException ('invalid deletion count') instead of refusing the commit (since 7.4.0)

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

What it shows

You commit a SegmentInfos whose only segment has 2 documents, one real hard delete (delCount 1, with its live-docs file) and a softDelCount of 2, so each count is within maxDoc but together they claim 3 deleted documents out of 2. You expect SegmentInfos.commit to refuse it with IllegalStateException 'cannot write segment', as it already does when either count alone exceeds maxDoc, or else to write a commit that can be read back. Instead commit succeeds, and SegmentInfos.readLatestCommit, DirectoryReader.open and IndexWriter then fail on the new segments_N with CorruptIndexException 'invalid deletion count: 3 vs maxDoc=2', because the write side never checks the sum that the read side rejects.

Expected vs actual

  • Expected: sis.commit(dir) throws IllegalStateException: cannot write segment: ..., as it does when either count alone exceeds maxDoc.
  • Actual: commit returns; readLatestCommit then throws CorruptIndexException: invalid deletion count: 3 vs maxDoc=2, with assertions on and off.
