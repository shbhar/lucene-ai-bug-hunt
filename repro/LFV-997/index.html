AI-assisted bug hunt in Apache Lucene

SortRescorer and Expression#getRescorer size their sort collector by topN instead of by the number of first-pass hits, so a topN far above the hit count (such as Integer.MAX_VALUE for 're-sort them all') throws (OutOfMemoryError on main, IllegalArgumentException in current releases) or allocates memory in proportion to topN, while QueryRescorer and DoubleValuesSourceRescorer return the hits

Bug page for LFV-997

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

What it shows

You run a first-pass search that returns 5 hits and re-sort them with new SortRescorer(sort).rescore(searcher, firstPass, Integer.MAX_VALUE), meaning 're-sort all of them'; you expect the 5 hits back in sort order, as topN = 5 or 10 give and as QueryRescorer and DoubleValuesSourceRescorer give for any topN. Instead the call throws OutOfMemoryError 'Requested array size exceeds VM limit' on main (IllegalArgumentException 'maxSize must be >= 0 and < 2147483631' in 10.x and 9.x), because SortRescorer sizes its TopFieldCollector, which pre-allocates its arrays, by topN instead of by the number of hits it was given. Smaller large values succeed but cost memory in proportion to topN (about 120 MB for 4 hits at topN = 10^7), and Expression#getRescorer inherits the same code.

The test shows that SortRescorer.rescore with topN = Integer.MAX_VALUE ('re-sort all hits') fails on 2 first-pass hits, because it sizes its TopFieldCollector by topN instead of by the hit count.

Expected vs actual

Expected: the 2 hits come back re-sorted (as with topN = 2). Actual (-ea and -da): OutOfMemoryError 'Requested array size exceeds VM limit' at SortRescorer.rescore:49 (IllegalArgumentException in 10.x/9.x releases).
