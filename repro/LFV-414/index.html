AI-assisted bug hunt in Apache Lucene

LongRangeGroupSelector and DoubleRangeGroupSelector load their per-segment values only in setScorer, so grouping with score-less caching returns wrong groups (8.6.0-10.5.2) or throws NullPointerException (10.6.0 and main), and DistinctValuesCollector with a range value selector always throws NullPointerException

Finding LFV-414Area: grouping / range group selectors (LongRangeGroupSelector, DoubleRangeGroupSelector) on scorer-less collection paths: the GroupingSearch score-less cache replay and the DistinctValuesCollector value selectorPriority: mediumImpact: silent wrong resultsNovelty: known upstream

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

What it shows

You group a two-segment index (prices 5, 15, 25 | 35, 45, 55) into price ranges with GroupingSearch and new LongRangeGroupSelector(price, new LongRangeFactory(0, 20, 60)), sort by a field, and turn on the documented second-pass cache without scores, setCaching(100, false); you expect the same groups as without the cache: LongRange(0, 20) -> docs 0, 1, LongRange(20, 40) -> 2, 3, LongRange(40, 60) -> 4, 5. Instead every release from 8.6.0 to 10.5.2 returns LongRange(0, 20) -> none, LongRange(20, 40) -> 0, 3 and LongRange(40, 60) -> 1, 2, 4, 5 with no error (the first segment's documents are grouped by the second segment's prices), 10.6.0 and main throw NullPointerException, and DistinctValuesCollector with a range selector as its value selector throws NullPointerException in every version; DoubleRangeGroupSelector behaves the same. The cause is that both range selectors fetch their per-segment values only in setScorer(), while the score-less cache replay and DistinctValuesCollector's per-group collector call setNextReader and advanceTo on the selector but never setScorer.

Expected vs actual

  • Expected: You expect the same groups as without the cache: LongRange(0, 20) -> docs 0, 1, LongRange(20, 40) -> 2, 3, LongRange(40, 60) -> 4, 5.
  • Actual: Every release from 8.6.0 to 10.5.2 returns LongRange(0, 20) -> none, LongRange(20, 40) -> 0, 3 and LongRange(40, 60) -> 1, 2, 4, 5 with no error (the first segment's documents are grouped by the second segment's prices), 10.6.0 and main throw NullPointerException, and DistinctValuesCollector with a range selector as its value selector throws NullPointerException in every version; DoubleRangeGroupSelector behaves the same.
