SimpleNaiveBayesDocumentClassifier returns NaN for every class and null from assignClass when the document has a field value with no tokens (empty, stop words only or punctuation only), because each value's log-likelihood is divided by its token count (released since 6.0.0)

Bug LFV-380Area: classification / document classifiers (SimpleNaiveBayesDocumentClassifier.assignClass and getClasses)Priority: mediumImpact: silent wrong resultsNovelty: new

Bug page for LFV-380

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

What it shows

You train SimpleNaiveBayesDocumentClassifier on the fields title and body and classify the document {title: 'apple', body: ''} (or a body such as 'the of and' that the analyzer reduces to stop words), expecting a class with a finite score, as the DocumentClassifier.assignClass javadoc and the '0-1 range' normalisation comment imply and as the same document without the body value gets (fruit). Instead getClasses returns fruit=NaN and vehicle=NaN, and assignClass returns null. calculateLogLikelihood returns result / tokenizedText.length, which is 0.0 / 0 = NaN for a value with no tokens; assignNormClasses adds that NaN to every class, and neither the log-sum-exp normalisation nor the 'score > maxscore' test in assignClass can recover from it.

Expected vs actual

  • Expected: getClasses returns finite probabilities that sum to 1 and assignClass a class; without the body value: fruit 0.7619, vehicle 0.2381.
  • Actual: getClasses=[fruit=NaN vehicle=NaN ] assignClass=null for body "", "To be or not to be" and "!!!"; no exception.
