# RegExp CASE_INSENSITIVE matching is asymmetric for U+0130 and U+0131 (dotted and dotless i)

Bug LFV-023 · Area: util / automaton · Priority: low · Impact: silent wrong results · Novelty: new

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

## What it shows

You match text that contains U+0130 or U+0131 with a CASE_INSENSITIVE RegExp. You expect case-insensitive matching to be symmetric (the study compared against ICU4J and java.util.regex). Instead the result depends on which member of the pair is in the pattern and which is in the text.

## Expected vs actual

- Expected: You expect case-insensitive matching to be symmetric (the study compared against ICU4J and java.util.regex).
- Actual: The result depends on which member of the pair is in the pattern and which is in the text.
