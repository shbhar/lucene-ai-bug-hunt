# TaskExecutor#invokeAll returns while a task is still running if the caller is interrupted

Bug LFV-056 · Area: search / concurrency · Priority: low · Impact: wrong error · Novelty: new

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

## What it shows

You run a concurrent search and the calling thread is interrupted. You expect invokeAll to wait for its tasks or to propagate their failures. Instead it returns while a task still runs: with assertions on an AssertionError fires, and with assertions off the task's exception is lost and the task may keep reading a reader the caller has released.

The test shows that when the calling thread is interrupted while it runs its own task, TaskExecutor#invokeAll ends while the task on the executor thread is still running.

## Expected vs actual

Expected: invokeAll ends (normally or with ThreadInterruptedException) only after every task has completed ("wait for them to complete"). Actual: -ea AssertionError "Some tasks are still running?" (TaskExecutor.java:130), -da ThreadInterruptedException, both while task 0 still runs.
