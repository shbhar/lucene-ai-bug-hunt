Test suite on branch_11x and main (both unreleased): the two testDictionaryReuse tests added by #14397 fail for some seeds, because they assert one segment on a writer made with newIndexWriterConfig(), which for some seeds sets maxBufferedDocs so low (2..6 for the seven documents of the stored-fields test, 2..5 for the six of the term-vectors test) that the documents are flushed into several segments; the failures do not come from the code under test

What it shows

You run Lucene's own tests on branch_11x (to become 11.0.0) or on main and expect TestCompressingStoredFieldsFormat.testDictionaryReuse and TestCompressingTermVectorsFormat.testDictionaryReuse, the two tests added with #14397, to pass unless the code they test is wrong. Instead they fail for some seeds with 'java.lang.AssertionError: expected:<1> but was:<2>' (in other runs 3, and 4 for the stored-fields test), for example both with the master seed 8621B64601478ADE: each asserts that its seven or six documents are one segment, on a writer made with newIndexWriterConfig() and NoMergePolicy, and for some seeds that helper of the test framework sets maxBufferedDocs to a value of 2..6 (2..5 for the six documents), so the writer flushes several segments and nothing merges them. It is a false alarm of the two tests, not a wrong stored value or term vector: the assertion fails before the test reads a stored value or term vector, and the same seeds pass once the tests pin maxBufferedDocs (run with .setMaxBufferedDocs(100) on the two writer configs); the tests are on branch_11x (to become 11.0.0; since the backport 15b6826d849f of 2026-11-19) and on main, both unreleased, and in no release; on a build of branch_11x 5d7ca54ba503 the same master seed fails both tests, with assertions on and off.

Expected vs actual

  • Expected: One segment: assertEquals(1, reader.leaves().size()) holds, as both testDictionaryReuse tests assert.
  • Actual: java.lang.AssertionError: expected:<1> but was:<2> for the one test of this page with its seed 7D797B773AD37D33; Lucene's own two tests with the seed 8621B64601478ADE: but was:<3> (stored fields) and but was:<2> (term vectors).
