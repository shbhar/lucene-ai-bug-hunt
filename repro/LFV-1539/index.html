AI-assisted bug hunt in Apache Lucene

A scoring JoinUtil term join (ScoreMode Max, Min, Avg or Total, run where scores are needed) throws IllegalArgumentException 'cost must be >= 0' on a segment whose Terms#size() for the join's to-field returns -1, the value its javadoc documents for a term count that is not stored: TermsIncludingScoreQuery multiplies maxDoc by it. Run with an application's reader view that reports -1; on 10.6.0, branch_11x and main the stock postings formats and six stock reader views that were run report a real count (the join throws on 6.1.0 to 10.6.0, branch_11x and main)

What it shows

You put an index reader behind a view whose Terms#size() returns -1, the value the javadoc documents for a term count that is not stored, and run a JoinUtil term join that maps scores (ScoreMode.Max) on it. You expect the hit and the score that the plain reader gives; the same view answers the same join without scores (ScoreMode.None) correctly. Instead IndexSearcher.search throws IllegalArgumentException 'cost must be >= 0, got -2' (the test's segment has two documents): to estimate its cost the join's query multiplies the segment's maxDoc by the to-field's term count, gets a negative number and hands it to an iterator whose constructor rejects it. Read without such a view, an index written with the stock postings formats that were run on 10.6.0, branch_11x and main did not show it: they report a real count.

Expected vs actual

  • Expected: searcher.search(join, 10) returns 1 hit, the "to" document, as the plain reader does and as the same view does for the join without scores.
  • Actual: java.lang.IllegalArgumentException: cost must be >= 0, got -2, thrown by BitSetIterator's constructor while the join's scorer is built.

  • Tested on Lucene branch_11x 89e68e0f3a50 (a commit of 2026-11-17): reproduced.
  • A branch_11x checkout builds 11.0.0-SNAPSHOT jars, so set V=11.0.0-SNAPSHOT there. Against the 10.6.0 release jars the test as shipped does not compile, because LeafReader#terms declares IOException there: on line 38 write 'public Terms terms(String field) throws java.io.IOException'. With that change it fails 1 of 1 on those jars, with and without assertions, with the same message.
