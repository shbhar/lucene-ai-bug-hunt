AI-assisted bug hunt in Apache Lucene

Operations.repeat(a, min, max) does not check for a negative min and silently returns a wrong language: on main and since 10.2.0 repeat(x, -1, 1) accepts "xx" (two repetitions, above max) and rejects ""; every release since 4.0.0 is wrong for min < 0 < max, in a different form before 10.2.0

What it shows

You build a bounded-repetition automaton with Operations.repeat(Automata.makeChar('x'), -1, 1), for example with a lower bound computed in your own code that went below 0. You expect what the javadoc promises, an automaton that accepts between min and max (including both) repetitions, here "" and "x", or else an IllegalArgumentException for the negative min. Instead, on main and 10.2.0 to 10.6.0, the result accepts "x" and "xx" (two repetitions although max is 1) and rejects "", because the only bound check is min > max and a negative min turns the mandatory prefix into an empty concatenation (since 10.2.0 a 0-state automaton) to which max - min optional copies are appended; 4.10.0 to 10.1.x return the empty language and 4.0.0 to 4.9.x accept "", "x" and "xx" instead.

Expected vs actual

  • Expected: repeat throws IllegalArgumentException, or its automaton rejects "xx" and accepts ""; the test passes.
  • Actual: The automaton accepts "xx": AssertionError: 2 repetitions accepted, but max is 1 at line 32, with assertions on and off.
