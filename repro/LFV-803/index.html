UnifiedHighlighter's re-analysis offset strategies decode every extracted query term as UTF-8, so a binary term (for example a binary StringField id reached with requireFieldMatch=false) makes highlighting throw

Bug LFV-803Area: highlighter / UnifiedHighlighter re-analysis offset strategies (MemoryIndexOffsetStrategy, TokenStreamOffsetStrategy)Priority: mediumImpact: crashNovelty: known upstream

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

What it shows

You build UnifiedHighlighter.builder(null, analyzer).withFieldMatcher(f -> true) (the documented requireFieldMatch=false switch) and call highlightWithoutSearcher("body", query, "hello world", 1) with query = SHOULD id:<binary bytes 9F 12 FF 00 41> + SHOULD body:hello, and expect "<b>hello</b> world", because binary terms are documented Lucene input (StringField's BytesRef constructor), the id term can never occur in analyzed text, the byte-based POSTINGS and TERM_VECTORS offset sources do not throw on such a term, and the classic Highlighter and the default field matcher highlight the same query. Instead the call throws: the default MemoryIndexOffsetStrategy passes the raw term bytes to Automata.makeStringUnion, which is documented to take UTF-8 and throws IllegalArgumentException 'Invalid UTF8 header byte: 0x9f', and TokenStreamOffsetStrategy (withPassageRelevancyOverSpeed(false)) calls BytesRef.utf8ToString, which throws AssertionError with -ea and ArrayIndexOutOfBoundsException with -da. The same happens through highlight on a stored text field without offsets, and on a field with offsets when the query also has a prefix clause on it.

Expected vs actual

  • Expected: The test passes: it asserts the documented behaviour.
  • Actual: The call throws: the default MemoryIndexOffsetStrategy passes the raw term bytes to Automata.makeStringUnion, which is documented to take UTF-8 and throws IllegalArgumentException 'Invalid UTF8 header byte: 0x9f', and TokenStreamOffsetStrategy (withPassageRelevancyOverSpeed(false)) calls BytesRef.utf8ToString, which throws AssertionError with -ea and ArrayIndexOutOfBoundsException with -da.
