What it shows

You index vectors with FaissKnnVectorsFormat (a sandbox, experimental vector format that is new in 11.0 and needs the Faiss native library), and the Directory throws while the library is writing or reading a segment's index: the disk refuses a write during a flush or a merge, IndexWriter.rollback() aborts a running merge, or a read fails while a reader opens. You expect the exception to reach your call (commit, rollback, DirectoryReader.open), as in the control runs with Lucene99HnswVectorsFormat, where commit() throws the IOException and rollback() during a merge returns normally. Instead the JVM prints the exception's stack trace and a line that ends 'The VM will now exit', and the whole process exits with code 1, because the format's read and write callbacks are called from native code and let the exception escape.

Expected vs actual

  • Expected: commit() throws the directory's IOException and the child JVM ends with exit code 0.
  • Actual: The child JVM prints the IOException (frame FaissLibraryNativeImpl.writeBytes:79), then Unrecoverable uncaught exception encountered. The VM will now exit, and exits with code 1 (expected:<0> but was:<1> at line 69).

Run it

  • Tested on Lucene branch_11x daa54f2e0cd3 (a commit of 2026-11-13): reproduced.
  • What the test does: its main method opens an IndexWriter with FaissKnnVectorsFormat on an in-memory Directory whose outputs throw IOException('no space left on device') from writeBytes on the Faiss data file (.faissd) once a flag is set, adds one document with a two-dimensional vector, sets the flag and expects commit() to throw. The test method runs that main method in a child JVM (the same assertion setting, library path and class path) and asserts that the child's exit code is 0. It fails with 'exit code of the child JVM, which printed: ...', then the child's output (the stack trace of java.io.IOException: no space left on device with the frame FaissLibraryNativeImpl.writeBytes, and the JVM's line 'Unrecoverable uncaught exception encountered. The VM will now exit') and 'expected:<0> but was:<1>', the same with and without assertions: the child JVM exited with code 1 where commit() should have thrown. Only the child JVM exits; the JVM that runs the test stays up and reports the failure. Do not call the main method in a JVM that other work shares: it ends that JVM. The test needs the Faiss C library (libfaiss_c 1.11.0 with the libraries it depends on), which this site does not ship. Install it as the Javadoc of the package org.apache.lucene.sandbox.codecs.faiss describes and, on Linux, put its directory on LD_LIBRARY_PATH before the commands (export LD_LIBRARY_PATH=/path/to/faiss/lib) or add -Djava.library.path=/path/to/faiss/lib to the java command; nothing else is needed. Without the library the test class is skipped: the launcher prints 'Dependencies present' beside the class name, '1 tests skipped' and '0 tests failed', and exits with 0. A skip is not a pass and says nothing about the finding. A failure whose printed child output has no 'The VM will now exit' line is not this finding either. On a branch_11x checkout set V=11.0.0-SNAPSHOT.
