AI-assisted bug hunt in Apache Lucene

Sequential DrillSideways#search(DrillDownQuery, CollectorManager, List) can throw CollectionTerminatedException to its caller when the collector of a drill-sideways dimension declines a segment from getLeafCollector, where IndexSearcher.search with the same collector manager and a DrillSideways built with an executor return the result (run: the sandbox HistogramCollectorManager on a reader with a segment whose field infos lack the histogram field; each release from 10.2.0 to 10.6.0, branch_11x and main)

Finding LFV-1583Area: facet / DrillSideways, sequential mode (DrillSidewaysQuery, the driver of the drill-sideways collectors of a segment)Priority: lowImpact: crashNovelty: new

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

What it shows

You index two segments, of which only the first has a document with the numeric doc-values field 'price', and call DrillSideways#search(DrillDownQuery, CollectorManager, List) on a DrillSideways built without an executor, with one dimension (color=red) and the sandbox HistogramCollectorManager('price', 10) as the collector manager of that dimension. You expect the search to return with the histogram {0=1}, which IndexSearcher.search returns for the same manager on the same index and which the same call returns when the DrillSideways was built with an executor. Instead the search throws CollectionTerminatedException, an unchecked exception without a stack trace, with and without assertions, and returns nothing: the histogram collector declines the segment without the field by throwing that exception from getLeafCollector, the search loop of IndexSearcher has a handler around that call for the hit collector, and DrillSidewaysQuery asks each dimension's collector for its leaf collector inside Weight#scorerSupplier, which the loop calls after and outside that handler; no wrong result is returned and nothing is written. The searches of the class that count facets are not this case (FacetsCollector does not throw the exception), and the one stock collector found that triggers it is a class of the sandbox module.

The limits of the finding: the failure is loud (an unchecked exception without a stack trace; no wrong result is returned and nothing is written); the searches of DrillSideways that count facets are not this case, because FacetsCollector does not throw the exception; the one stock collector found that triggers it is a class of the sandbox module; and the same call on a DrillSideways built with an executor returned the result in the runs. What the test does: it writes two segments of one document each (NoMergePolicy keeps them apart), both documents with color=red and only the first with the numeric doc-values field 'price' (value 5); it builds a DrillDownQuery with the one dimension color=red and no base query and calls the three-argument DrillSideways#search on a DrillSideways built without an executor, with TopScoreDocCollectorManager(10, 10) for the hits and the sandbox HistogramCollectorManager('price', 10) for the dimension; it expects the count 1 in bucket 0 of the dimension's histogram. The search call throws org.apache.lucene.search.CollectionTerminatedException, so the test's assertion is not reached; the exception carries no stack trace, and the run prints its name with the seed line and no frame of Lucene. At main b5a4546a5964 the histogram collector throws it from getLeafCollector for a segment whose field infos lack the field (HistogramCollector.java:73), and DrillSidewaysQuery asks each dimension's collector for its leaf collector with no handler for the exception (DrillSidewaysQuery.java:168). What the javadoc says at that commit: the search method's, 'Search using DrillDownQuery with custom collectors. This method can be used with any {@link CollectorManager}s.' (DrillSideways.java:398-399), and the exception's, 'Throw this exception in {@link LeafCollector#collect(int)} to prematurely terminate collection of the current leaf.' and 'Note: IndexSearcher swallows this exception and never re-throws it.' (CollectionTerminatedException.java:20-23); the exception's javadoc names LeafCollector#collect(int) and IndexSearcher, and neither getLeafCollector nor DrillSideways. The release ranges differ by the trigger. With stock classes only, as in this test, the first release is 10.2.0, the first with the sandbox histogram collector: the test fails on each release from 10.2.0 to 10.6.0 and does not compile on 10.1.0. With a collector of the caller's own that declines a segment from getLeafCollector, in tests that are not shipped here, the call threw on each build it was run on: 9.12.0 (the first release with the three-argument search), 9.12.1, 9.12.2, 9.12.3, 10.0.0, 10.1.0, 10.2.0, 10.5.2, 10.6.0, branch_11x and main.
