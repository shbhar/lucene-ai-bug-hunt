AI-assisted bug hunt in Apache Lucene

An NRT DirectoryTaxonomyReader reopened during DirectoryTaxonomyWriter.replaceTaxonomy keeps the replaced taxonomy's ordinal/label caches and parent arrays, because the epoch is incremented only after the content change (wrong labels that persist, or ArrayIndexOutOfBoundsException from openIfChanged)

Bug LFV-482Area: facet / taxonomy NRT reopen (DirectoryTaxonomyWriter.replaceTaxonomy and deleteAll epoch vs DirectoryTaxonomyReader.doOpenIfChanged)Priority: lowImpact: silent wrong resultsNovelty: known upstream

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

What it shows

You keep a near-real-time taxonomy reader open on a DirectoryTaxonomyWriter and refresh it with openIfChanged while the writer swaps in a rebuilt taxonomy with replaceTaxonomy, for example [a, b] replaced by [b, a]. You expect the refreshed reader to show either the old taxonomy or the new one, each with its own ordinals and labels, as the reader/writer concurrency contract and the reader's own 'was the taxonomy recreated?' check intend. Instead, a refresh that lands after the new content is visible but before replaceTaxonomy increments its epoch is treated as a plain append and reuses the replaced taxonomy's caches and parent arrays: it answers getOrdinal(a)=1 and getPath(1)=a, facet counts over the new index (three b documents, one a) come out labelled 'a (3), b (1)' instead of 'b (3), a (1)', and every later openIfChanged returns null, so the wrong reader stays current until the taxonomy changes again (with a smaller replacement the refresh throws ArrayIndexOutOfBoundsException instead).

Expected vs actual

  • Expected: You expect the refreshed reader to show either the old taxonomy or the new one, each with its own ordinals and labels, as the reader/writer concurrency contract and the reader's own 'was the taxonomy recreated?' check intend.

Run it

  • Tested on Lucene main ea57360912ed (2026-10-24): reproduced.
  • How to read the outcome: a failing test is the bug reproducing (the failure message states expected against actual).
  • Seeds: a rerun with the same seed replays the same random choices. Assertions off (-da -dsa -Dtests.asserts=false) is the production-like setting.
# Lucene checkout at the tested commit, built with: ./gradlew --no-daemon assemble   (JDK 25)
LUCENE=/path/to/lucene; V=11.0.0-SNAPSHOT
