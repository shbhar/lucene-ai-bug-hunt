MoreLikeThis.retrieveInterestingTerms(int) throws NullPointerException after the documented setFieldNames(null) ('determined at runtime from the IndexReader'), unless like(int) or like(Map) ran first on the same instance

Bug LFV-577Area: queries / MoreLikeThis field-name resolution (setFieldNames(null) and the convenience method retrieveInterestingTerms(int))Priority: lowImpact: crashNovelty: known upstream

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

What it shows

You create a MoreLikeThis, call setFieldNames(null), which its javadoc documents as 'the field names to be determined at runtime from the IndexReader provided in the constructor', and ask retrieveInterestingTerms(docNum) for the interesting words of an indexed document. You expect the words that like(docNum) would put into its query, taken from all indexed fields. Instead the call throws 'NullPointerException: Cannot read the array length because "<local4>" is null' at MoreLikeThis.retrieveTerms (MoreLikeThis.java:715), because only like(int) and like(Map) replace null with the reader's indexed fields, so it works only if one of them ran first on the same instance.

Expected vs actual

  • Expected: You expect the words that like(docNum) would put into its query, taken from all indexed fields.
