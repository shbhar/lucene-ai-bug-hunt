AI-assisted bug hunt in Apache Lucene

geo.Rectangle checks minLat <= maxLat only with an assert, so a lat/lon box with swapped latitudes (new Rectangle, LatLonShape.newBoxQuery, a WKT ENVELOPE) throws a bare AssertionError with -ea and is silently accepted with -da, where LatLonShape box queries then return hits that match no region; the Cartesian twin XYRectangle throws IllegalArgumentException for the same mistake

Bug LFV-1014Area: core / geo Rectangle (LatLonShape box queries, newGeometryQuery(Rectangle), SimpleWKTShapeParser ENVELOPE)Priority: lowImpact: wrong errorNovelty: new

AI-assisted finding, confirmed by automated checks, not yet triaged by a human Lucene committer. This site files nothing upstream.

What it shows

You build a lat/lon box with the minimum and maximum latitude swapped, for example LatLonShape.newBoxQuery(field, INTERSECTS, 10, 5, 0, 1) or the WKT text ENVELOPE(0, 1, 5, 10), and expect an IllegalArgumentException, as XYRectangle gives for the same mistake and as Rectangle itself gives for an out-of-range latitude. Rectangle's constructor checks the order only with 'assert maxLat >= minLat', so with assertions enabled you get a bare AssertionError, and with assertions disabled the inverted box is accepted. The shape query then matches only shapes that cross both latitude lines (INTERSECTS) or the complement of those (DISJOINT), which is neither the empty result that LatLonPoint.newBoxQuery gives for the same box nor the result of the swapped box.

The test shows that new Rectangle(minLat 10, maxLat 5, minLon 0, maxLon 1) is not rejected with an IllegalArgumentException: the latitude order is checked only by assert maxLat >= minLat (XYRectangle throws IllegalArgumentException for the same mistake).

Expected vs actual

Expected: IllegalArgumentException; actual: a bare java.lang.AssertionError from Rectangle.<init>(Rectangle.java:94) with -ea, and Expected exception IllegalArgumentException but no exception was thrown (box accepted) with -da.
